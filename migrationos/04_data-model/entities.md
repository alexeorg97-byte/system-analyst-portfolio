# Entities — MigrationOS

## 1. Назначение документа

Документ описывает основные бизнес- и системные сущности платформы MigrationOS.

Entities нужны, чтобы:

- зафиксировать назначение каждой сущности;
- описать ключевые поля и связи;
- показать владельцев данных;
- определить бизнес-правила для сущностей;
- подготовить основу для data dictionary, SQL schema, API и тестирования;
- связать модель данных с ролями, процессами и интеграциями.

Документ является продолжением [ERD](./erd.md).

---

## 2. Группы сущностей

| Группа | Сущности |
|---|---|
| Пользователи и доступ | `User`, `Role` |
| Мигранты и работодатели | `Migrant`, `Employer`, `Project` |
| Документы | `Document`, `DocumentFile` |
| Запросы | `Request` |
| Маркетплейс | `Service`, `ServiceOrder` |
| Финансы | `Payment`, `Invoice` |
| РКЛ и риски | `RklCheck`, `RiskScore` |
| Коммуникации | `Notification`, `ChatThread`, `ChatMessage` |
| Логи | `AuditLog`, `IntegrationLog` |

## 3. `User`

### 3.1. Назначение

`User` — учетная запись пользователя MigrationOS.

Сущность используется для:

- авторизации;
- определения роли пользователя;
- связи с мигрантом, работодателем или сотрудником агентства;
- проверки permissions;
- отображения пользователя в интерфейсе;
- записи действий в audit log.

### 3.2. Типы пользователей

| Тип | Описание |
|---|---|
| Мигрант | Пользователь мобильного приложения |
| Представитель работодателя | Пользователь кабинета работодателя |
| Менеджер агентства | Внутренний пользователь админ-панели |
| Supervisor | Руководитель или старший пользователь агентства |
| Superadmin | Системный администратор платформы |

### 3.3. Владелец данных

Основной владелец данных: платформа MigrationOS.

Источники наполнения:

- сам пользователь при регистрации или входе;
- менеджер агентства;
- импорт из внешних систем для внутренних ролей, если предусмотрено.

### 3.4. Ключевые поля

| Поле | Тип данных | Обязательное | Описание |
|---|---|---:|---|
| `id` | UUID | Да | Уникальный идентификатор пользователя |
| `role_id` | UUID | Да | Ссылка на роль |
| `email` | string | Нет | Email, используется для web-ролей |
| `phone` | string | Нет | Телефон, используется для мигранта и OTP |
| `password_hash` | string | Нет | Хэш пароля для web-доступа |
| `status` | enum | Да | Статус пользователя |
| `last_login_at` | datetime | Нет | Последний успешный вход |
| `created_at` | datetime | Да | Дата создания |
| `updated_at` | datetime | Да | Дата обновления |

### 3.5. Статусы

| Статус | Значение |
|---|---|
| `active` | Пользователь активен |
| `blocked` | Пользователь заблокирован |
| `pending` | Пользователь создан, но еще не активирован |
| `archived` | Пользователь архивирован |

### 3.6. Связи

| Связь | Кардинальность | Описание |
|---|---|---|
| `Role` → `User` | 1:N | Пользователь имеет одну системную роль |
| `User` → `Migrant` | 1:0..1 | Пользователь может быть связан с карточкой мигранта |
| `Employer` → `User` | 1:N | У работодателя может быть несколько пользователей |
| `User` → `AuditLog` | 1:N | Действия пользователя пишутся в audit log |

### 3.7. Бизнес-правила

| ID | Правило |
|---|---|
| ENT-USER-001 | Пользователь должен иметь роль |
| ENT-USER-002 | Внутренние пользователи должны проходить 2FA |
| ENT-USER-003 | Заблокированный пользователь не может авторизоваться |
| ENT-USER-004 | Изменение роли пользователя должно логироваться |
| ENT-USER-005 | Мигрант может быть связан только со своей карточкой |

## 5. `Migrant`

### 5.1. Назначение

`Migrant` — карточка иностранного работника.

Сущность является центральной для MigrationOS и связывает документы, работодателя, проект, РКЛ-проверки, риск-статус, заявки, запросы и коммуникации.

### 5.2. Владелец данных

Основной владелец данных: агентство.

Частичные источники данных:

- менеджер агентства;
- сам мигрант через мобильное приложение;
- работодатель в рамках согласованных сценариев;
- внешние системы и интеграции.

### 5.3. Ключевые поля

| Поле | Тип данных | Обязательное | Описание |
|---|---|---:|---|
| `id` | UUID | Да | Уникальный идентификатор мигранта |
| `user_id` | UUID | Нет | Связанный пользователь мобильного приложения |
| `employer_id` | UUID | Нет | Работодатель мигранта |
| `project_id` | UUID | Нет | Внутренний проект агентства |
| `manager_id` | UUID | Нет | Ответственный менеджер |
| `full_name` | string | Да | ФИО |
| `birth_date` | date | Да | Дата рождения |
| `phone` | string | Нет | Телефон |
| `passport_number` | string | Нет | Номер паспорта |
| `citizenship` | string | Нет | Гражданство |
| `status` | enum | Да | Статус карточки |
| `created_at` | datetime | Да | Дата создания |
| `updated_at` | datetime | Да | Дата обновления |

### 5.4. Статусы

| Статус | Значение |
|---|---|
| `active` | Карточка активна |
| `pending` | Карточка создана, но данные неполные |
| `blocked` | Доступ мигранта ограничен |
| `archived` | Карточка архивирована |

### 5.5. Связи

| Связь | Кардинальность | Описание |
|---|---|---|
| `Employer` → `Migrant` | 1:N | Работодатель может иметь много мигрантов |
| `Project` → `Migrant` | 1:N | Проект объединяет мигрантов |
| `Migrant` → `Document` | 1:N | У мигранта много документов |
| `Migrant` → `Request` | 1:N | Мигрант может создавать запросы |
| `Migrant` → `ServiceOrder` | 1:N | Заявки могут быть связаны с мигрантом |
| `Migrant` → `RklCheck` | 1:N | История РКЛ-проверок |
| `Migrant` → `RiskScore` | 1:1 | Текущий риск |

### 5.6. Бизнес-правила

| ID | Правило |
|---|---|
| ENT-MIG-001 | Мигрант видит только свою карточку |
| ENT-MIG-002 | Работодатель видит только мигрантов своей организации |
| ENT-MIG-003 | `Project` не является работодателем или tenant |
| ENT-MIG-004 | Карточка мигранта может существовать без активного пользователя |
| ENT-MIG-005 | Критичные изменения карточки должны логироваться |
| ENT-MIG-006 | Архивная карточка не должна давать доступ в мобильное приложение |
