# Functional Requirements — MigrationOS

## 1. Назначение документа

Документ описывает функциональные требования к платформе MigrationOS.

Функциональные требования фиксируют, что система должна делать для поддержки бизнес-процессов миграционного сопровождения, взаимодействия с работодателями, работы мобильного приложения мигранта, административной панели, маркетплейса услуг, интеграций и уведомлений.

Документ используется для:

- декомпозиции бизнес-требований в функции системы;
- постановки задач разработке;
- подготовки acceptance criteria;
- проектирования API, модели данных и интерфейсов;
- подготовки тест-кейсов и чек-листов.

| FR-141 | Мобильное приложение мигранта должно поддерживать RU / UZ / EN | Must | BR-010 |
| FR-142 | Все пользовательские тексты в мобильном приложении должны использовать ключи локализации | Must | BR-010 |
| FR-143 | Push-уведомления мигранта должны отправляться на выбранном языке | Must | BR-010 |
| FR-144 | Если перевод отсутствует, система должна использовать fallback-язык | Should | BR-010 |

## 18. Приоритеты

Для функциональных требований используется MoSCoW:

| Приоритет | Значение |
|---|---|
| Must | Обязательно для MVP, безопасности, юридической корректности или ключевого бизнес-процесса |
| Should | Важно для продукта, но может быть реализовано после базового MVP |
| Could | Полезно, но не критично для первой версии |
| Won't | Не входит в текущую версию |

---

## 19. Ограничения документа

- Документ описывает функциональное поведение системы, но не заменяет API-контракты.
- Детальные request/response описываются в разделе API.
- Детальная ERD и словарь данных описываются в разделе Data Model.
- Нефункциональные требования описываются отдельно в NFR.
- Детальные тест-кейсы описываются в разделе Testing.
- Требования могут уточняться после согласования открытых вопросов по РКЛ, 1С, платежам и маркетплейсу.
