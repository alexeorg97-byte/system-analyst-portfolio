# Acceptance Criteria — MigrationOS

## 1. Назначение документа

Документ описывает критерии приемки для ключевых сценариев платформы MigrationOS.

Acceptance Criteria нужны, чтобы:

- определить, когда требование считается выполненным;
- связать user stories с проверяемым поведением системы;
- подготовить основу для тест-кейсов;
- снизить неоднозначность между аналитиком, разработкой, QA и бизнесом;
- проверить ключевые сценарии MVP.

Критерии оформлены в формате:

```gherkin
Given [исходное состояние]
When [действие пользователя или событие]
Then [ожидаемый результат]
```

---

## 2. Область покрытия

Документ покрывает ключевые MVP-сценарии:

1. Авторизация мигранта и сотрудников агентства.
2. Просмотр и загрузка документов мигранта.
3. Создание запросов и заявок.
4. Сценарии работодателя.
5. Работа в административной панели.
6. Маркетплейс услуг.
7. Платежи и счета.
8. РКЛ-проверки и риск-статусы.
9. Уведомления.
10. Роли и доступ.

## 3. Критерии приемки

### AC-001. Вход мигранта по OTP

**Связанные User Stories:** `US-MIG-001`  
**Связанные FR:** `FR-001`, `FR-002`, `FR-003`

```gherkin
Given мигрант находится на экране входа
When он вводит корректный номер телефона и запрашивает OTP-код
Then система отправляет OTP-код и показывает экран подтверждения
```

```gherkin
Given мигрант получил OTP-код
When он вводит корректный OTP-код в пределах срока действия
Then система авторизует мигранта и открывает главный экран приложения
```

```gherkin
Given номер телефона связан с карточкой мигранта
When мигрант успешно проходит OTP-аутентификацию
Then система привязывает сессию к существующей карточке мигранта
```

### AC-002. Ошибка входа мигранта, если карточка не найдена

**Связанные User Stories:** `US-MIG-001`  
**Связанные FR:** `FR-004`

```gherkin
And показывает понятное сообщение о невозможности входа
And предлагает сценарий обращения к менеджеру
```

### AC-004. Просмотр списка документов мигрантом

**Связанные User Stories:** `US-MIG-004`, `US-MIG-005`  
**Связанные FR:** `FR-020`, `FR-021`, `FR-022`

```gherkin
Given мигрант авторизован в приложении
When он открывает раздел документов
Then система показывает список документов, связанных с его карточкой
And для каждого документа отображает тип и статус
And отображает срок действия, если он применим
```

```gherkin

When мигрант открывает список документов
Then система не требует обязательного отображения даты истечения
And не помечает такой документ как просроченный только из-за отсутствия expiry date
```

```gherkin

Then система отклоняет загрузку
```

## 4. Правила приемки документа

- Каждый критерий приемки должен быть привязан как минимум к одной `User Story`.
- Каждый критерий приемки должен быть привязан как минимум к одному `FR`.
- Формулировка критерия должна быть наблюдаемой и проверяемой.
- Если сценарий зависит от роли, это должно быть отражено в `Given`.
- Если сценарий зависит от внешнего события, это должно быть отражено в `When`.

---

## 5. Ограничения документа

- Документ не заменяет детальные тест-кейсы.
- Для одного `FR` может существовать несколько критериев приемки.
- Детальные негативные, пограничные и нагрузочные сценарии выносятся в тест-кейсы и edge cases.
- Критерии приемки могут уточняться после детализации статусных моделей и BPMN-процессов.
