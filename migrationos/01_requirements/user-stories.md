# User Stories — MigrationOS

## 1. Назначение документа

Документ описывает пользовательские истории для платформы MigrationOS.

User Story фиксирует потребность пользователя в формате:

> Как [роль], я хочу [действие или возможность], чтобы [ценность или результат].

Документ нужен, чтобы:

- связать требования с реальными целями пользователей;
- показать ценность функций для мигранта, работодателя, менеджера и руководителя;
- подготовить основу для acceptance criteria;
- декомпозировать функциональность на понятные сценарии;
- помочь разработке, QA и дизайну понять пользовательский контекст.

---

## 2. Роли пользователей

В документе используются следующие роли:

| Роль | Описание |
|---|---|
| Мигрант | Иностранный работник, использующий мобильное приложение |
| Работодатель | Компания-клиент агентства, использующая веб-кабинет |
| Менеджер агентства | Сотрудник агентства, работающий в админ-панели |
| Руководитель агентства | Пользователь с расширенным доступом к аналитике, рискам и контролю процессов |
| Superadmin | Технический администратор системы |
| Финансовый специалист | Пользователь или стейкхолдер, отвечающий за счета, оплаты и сверку |
| Compliance / юридический блок | Стейкхолдер, влияющий на требования к документам, ПДн, доступам и аудиту |

## 10. Приоритеты

Для user stories используется MoSCoW:

| Приоритет | Значение |
|---|---|
| Must | Критично для MVP, безопасности, юридической корректности или ключевого пользовательского сценария |
| Should | Важно для пользовательской ценности, но может быть реализовано после базового MVP |
| Could | Полезно, но не критично для первой версии |
| Won't | Не входит в текущую версию |

## 11. Связь user stories с требованиями

User Stories связаны с функциональными требованиями через поле “Связанные FR”.

Пример:

| User Story | Связанные FR | Что это показывает |
|---|---|---|
| US-MIG-006 | FR-023, FR-024, FR-025 | История мигранта про загрузку документа раскрывается через требования к загрузке, валидации и хранению файла |
| US-EMP-003 | FR-051, FR-124 | История работодателя про доступ только к своим мигрантам раскрывается через требования к видимости данных и backend authorization |
| US-MAN-008 | FR-072, FR-073 | История менеджера про смену статусов раскрывается через требования к lifecycle и истории изменений |

---

## 12. Ограничения документа

- User Stories не заменяют функциональные требования.
- Детальные acceptance criteria описываются в отдельном документе.
- API-контракты, ERD, роли и доступы описываются в отдельных артефактах.
- User Stories могут уточняться после детализации процессов BPMN и статусных моделей.
