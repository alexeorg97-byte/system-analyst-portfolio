# Lead Events

## Зачем нужна история событий

История событий нужна, чтобы видеть полный внутренний путь заявки: когда она была создана, что происходило с интеграциями, когда менялся статус и какие действия выполняли менеджеры. Это помогает не терять контекст и быстрее разбирать проблемные кейсы.

## Какие события фиксируются

Сейчас фиксируются такие события:

- создание заявки
- успешная отправка в Telegram
- ошибка отправки в Telegram
- смена статуса
- добавление комментария менеджера

## Поля модели LeadEvent

- `id` — уникальный идентификатор события
- `leadId` — ссылка на заявку
- `lead` — связь с моделью `Lead`
- `type` — технический тип события
- `title` — короткий заголовок события
- `description` — дополнительное описание события
- `metadata` — JSON с дополнительными данными
- `createdAt` — дата и время события

## Связь Lead → LeadEvent

У одной заявки может быть много событий. Поэтому `Lead` связан с `LeadEvent` как один-ко-многим. Это позволяет хранить временную ленту действий по конкретной заявке и собирать всю историю в карточке лида.

## Зачем нужен metadata Json

`metadata` нужен для гибкого хранения дополнительных деталей, которые отличаются у разных типов событий. Например, для смены статуса туда можно положить `oldStatus` и `newStatus`, а для комментария — `commentId`. Это даёт гибкость без постоянного усложнения схемы отдельными полями.

## Как это помогает аудиту, поддержке и аналитике

События помогают:

- восстанавливать последовательность действий по заявке
- разбирать ошибки интеграций
- понимать, почему статус оказался текущим
- использовать историю как основу для будущих отчётов и аналитики
