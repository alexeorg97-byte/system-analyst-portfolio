# User management

## Зачем нужен раздел пользователей

`User management UI` нужен, чтобы администратор мог управлять доступом в админку без ручных правок базы данных или env-переменных.

Это покрывает:

- создание новых сотрудников
- смену роли
- деактивацию доступа
- сброс пароля
- аудит изменений

## Роли

Используются роли:

- `admin` — полный доступ к админке и управлению пользователями
- `operator` — работа с лидами и чатами
- `viewer` — режим просмотра без административного управления пользователями

## Кто может управлять пользователями

Управление пользователями доступно только роли `admin`.

Только `admin` может:

- открыть `/admin/users`
- создать пользователя
- изменить имя, роль и активность
- сбросить пароль

## Создание пользователя

Администратор может создать пользователя через `/admin/users/new`.

При создании:

- имя и email обязательны
- email приводится к lowercase
- пароль должен быть не короче 8 символов
- роль должна быть одной из `admin`, `operator`, `viewer`
- пароль сразу хэшируется

`passwordHash` не возвращается на клиент и plain password не пишется в `AuditLog`.

## Изменение роли и активности

На странице `/admin/users/[id]` можно изменить:

- `name`
- `role`
- `isActive`

Удаление пользователей в MVP не поддерживается. Вместо удаления используется деактивация через `isActive = false`.

## Сброс пароля

Пароль можно сбросить на странице пользователя.

Ограничения:

- новый пароль должен быть не короче 8 символов
- пароль не логируется
- в аудит пишется только факт сброса

## Защита последнего admin

Если в системе остался только один активный администратор:

- нельзя отключить его
- нельзя понизить его роль до `operator` или `viewer`

Пользователь увидит ошибку:

`Нельзя отключить или понизить последнего администратора`

## AuditLog

В аудит записываются события:

- `user_created`
- `user_updated`
- `user_password_reset`

Для них сохраняются:

- кто выполнил действие
- над каким `User`
- старые данные, где это уместно
- новые данные, где это уместно

Пароль и `passwordHash` в аудит не записываются.

## Ограничения MVP

- нет email-инвайтов
- нет восстановления пароля по email
- нет удаления пользователей
- нет детального RBAC по каждой кнопке
