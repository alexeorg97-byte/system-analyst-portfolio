# Users, Roles, AuditLog

## Зачем нужна модель User

Простой `ADMIN_PASSWORD` удобен только на самом старте, но он не позволяет:

- разделять доступ между несколькими сотрудниками
- понимать, кто именно изменил заявку или чат
- отключать отдельного пользователя без смены общего пароля

Модель `User` переводит админку на нормальный сценарий входа по `email + password` и готовит проект к дальнейшему управлению доступами.

## Роли

В MVP используются три роли:

- `admin` — полный доступ к админке, включая просмотр `AuditLog`
- `operator` — работа с заявками и чатами: статусы, комментарии, ответы, назначение и закрытие чатов
- `viewer` — только просмотр заявок и чатов без изменений

Проверки ролей выполняются на уровне API. Интерфейс также по возможности скрывает действия для `viewer`.

## Почему ADMIN_PASSWORD заменён на User

Теперь основной сценарий входа использует таблицу `User` и хранит пароль только в виде хеша.

Для мягкого перехода оставлен совместимый fallback:

- если в базе ещё нет пользователя
- и введены `ADMIN_EMAIL` / `ADMIN_PASSWORD`

логин может автоматически создать или обновить первого администратора.

## Создание первого админа

Используется script:

```bash
npm run admin:create
```

Скрипт читает переменные:

- `ADMIN_EMAIL`
- `ADMIN_NAME`
- `ADMIN_PASSWORD`

Если пользователь с таким email уже существует, script обновляет его имя, пароль и роль `admin`.

## Хранение паролей

Новые библиотеки не используются. Для хеширования применяется встроенный Node.js `crypto.scryptSync`.

Формат хранения:

```text
scrypt$salt$hash
```

В клиент и API `passwordHash` не возвращается.

## Что такое AuditLog

`AuditLog` фиксирует ключевые действия в админке и помогает понимать:

- кто изменил статус заявки
- кто добавил внутренний комментарий
- кто взял чат в работу
- кто закрыл чат
- кто вошёл или вышел из админки

Это важно для поддержки, разбора спорных ситуаций и базовой безопасности.

## Какие действия логируются

Сейчас в `AuditLog` сохраняются:

- `admin_login`
- `admin_logout`
- `lead_status_changed`
- `lead_comment_added`
- `chat_assigned`
- `chat_closed`
- `operator_message_sent`

Для действий, где это важно, пишутся `oldValue` и `newValue`.

## Ограничения MVP

- cookie `admin_session` хранит `userId`, без отдельной таблицы сессий
- нет refresh tokens
- нет полноценного RBAC UI
- нет восстановления пароля
- `Message` пока не хранит отдельный `operatorId`

## Что можно добавить дальше

- password reset
- полноценные серверные сессии
- `operatorId` в `Message`
- фильтры и поиск по `AuditLog`
- управление пользователями из UI
