# Backlog MoSCoW

## Must have

- **Лендинг**  
  Rationale: без публичной страницы нет канала привлечения лидов.
- **Форма заявки**  
  Rationale: основной способ конверсии для MVP.
- **Lead**  
  Rationale: базовая доменная сущность, без которой невозможно вести учёт обращений.
- **PostgreSQL**  
  Rationale: централизованное хранение заявок, чатов и служебных данных.
- **Telegram**  
  Rationale: быстрый операционный канал уведомления о новых заявках.
- **Админка**  
  Rationale: необходима для ручной обработки лидов.
- **Карточка заявки**  
  Rationale: нужна для детального просмотра и обработки отдельного обращения.
- **Статусы**  
  Rationale: позволяют управлять жизненным циклом лида.
- **UTM**  
  Rationale: минимально необходимая маркетинговая аналитика.
- **Базовый чат**  
  Rationale: альтернативный канал первичного захвата интереса пользователя.

## Should have

- **Comments**  
  Rationale: дают внутренний контекст по обработке лида.
- **LeadEvent**  
  Rationale: позволяет видеть историю жизненного цикла обращения.
- **IntegrationLog**  
  Rationale: нужен для прозрачности интеграций и диагностики ошибок.
- **Фильтры**  
  Rationale: упрощают работу с растущим списком лидов.
- **Real-time чат**  
  Rationale: улучшает операторский UX и скорость ответа.
- **Роли**  
  Rationale: разделяют зоны ответственности и снижают риск нежелательных изменений.
- **AuditLog**  
  Rationale: повышает контролируемость административных действий.

## Could have

- **CRM Bitrix24**  
  Rationale: полезно для дальнейшей операционной интеграции, но не критично для базового захвата лида.
- **IntegrationJob / retry**  
  Rationale: улучшает надёжность интеграций, но может быть отложен после запуска MVP.
- **Visitor**  
  Rationale: нужен для более зрелой модели идентификации и повторных визитов.
- **Внутренние AnalyticsEvent**  
  Rationale: дают более глубокую продуктовую аналитику, но не обязательны в первой версии.
- **Settings UI**  
  Rationale: повышает гибкость настройки, но не обязателен на старте.

## Won’t have for MVP

- **Полноценная BI-аналитика**  
  Rationale: для MVP достаточно UTM и Яндекс Метрики.
- **Сложная IAM-модель**  
  Rationale: базовых ролей достаточно для первого этапа.
- **Мобильное приложение**  
  Rationale: web-интерфейса достаточно для запуска и проверки гипотезы.
- **Многоканальный контакт-центр**  
  Rationale: MVP ограничен сайтом, Telegram и CRM-интеграцией.
