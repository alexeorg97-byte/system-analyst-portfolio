# ChatSession и Message

## Зачем нужны ChatSession и Message

`ChatSession` и `Message` нужны, чтобы сохранять реальную историю диалога из чат-виджета, а не только итоговую заявку. Это даёт контекст по тому, как пользователь пришёл к оставлению контакта, какие ветки сценария проходил и что именно писал в чате.

## Связь ChatSession → Message

Одна `ChatSession` содержит много сообщений `Message`.

`Message` хранит:

- `id`
- `chatSessionId`
- `sender`
- `text`
- `createdAt`

Такой формат позволяет последовательно сохранять бот-сообщения, ответы посетителя и системные сообщения.

## Связь ChatSession → Lead

`ChatSession` может быть связана с `Lead` через `leadId`.

Это работает так:

1. При первом открытии чата создаётся `ChatSession`
2. По мере сценария сохраняются `Message`
3. После успешной отправки заявки через `/api/lead` чат-сессия связывается с созданным `Lead`

Так админка показывает не только карточку заявки, но и историю диалога, из которого она появилась.

## Статусы ChatSession

На уровне текущей логики используются статусы:

- `active` — чат-сессия создана и диалог ещё идёт
- `waiting_operator` — пользователь запросил оператора
- `operator_replied` — оператор сохранил ответ в историю чата
- `lead_created` — из чат-сессии уже создана заявка
- `closed` — зарезервировано для будущих сценариев ручного закрытия

## Sender у Message

На уровне модели поддерживаются значения:

- `bot`
- `visitor`
- `system`
- `operator`

Сейчас публичный API принимает только:

- `bot`
- `visitor`
- `system`

`operator` оставлен на будущее, когда появится операторская админка и живой диалог.

## Почему сейчас без WebSocket

На этом этапе проекту не нужен real-time чат. Достаточно сохранять сценарный диалог через обычные HTTP-запросы:

- старт сессии
- запись отдельных сообщений
- создание `Lead`
- привязка чат-сессии к заявке

Это даёт устойчивую базу данных и историю общения без усложнения инфраструктуры.

## Как это готовит проект к real-time чату

Добавление `ChatSession` и `Message` подготавливает систему к следующим шагам:

- WebSocket events для живых сообщений
- админка чатов
- подключение оператора
- handoff от сценарного бота к человеку

То есть текущая модель уже закладывает структуру будущего real-time чата, даже если пока сам чат работает без сокетов и без ИИ.
