# Portfolio Case

## Краткий блок для резюме

**Пет-проект / lead management и real-time чат**  
**Системный аналитик + разработчик/интегратор | Стек: Next.js, TypeScript, PostgreSQL, Prisma, Socket.IO, Telegram Bot API, CRM API, Яндекс Метрика, Nginx, PM2, VPS**

- Спроектировал и реализовал end-to-end систему захвата и обработки лидов с лендинга и чат-виджета.
- Описал доменную модель `Lead`, `ChatSession`, `Message`, `User`, `AuditLog`, `IntegrationLog`.
- Реализовал REST API и WebSocket-контракт для сценарного и real-time чата.
- Настроил Telegram и CRM-интеграции с журналированием результата по каждой интеграции.
- Построил admin panel с ролями `admin/operator/viewer`, аудитом и user management UI.
- Подготовил комплект аналитической документации: архитектура, ERD, API, процессы, требования, тесты.

## Роль

Системный аналитик + full-stack разработчик / интегратор.

## Контекст

Задача проекта — создать MVP-систему для получения обращений с сайта, быстрого контакта с потенциальным клиентом и последующей обработки лида внутри административного интерфейса.

## Вызов

Нужно было объединить в одном решении:

- публичный лендинг
- форму заявки
- чат-виджет
- real-time handoff на оператора
- Telegram-уведомления
- CRM-интеграцию
- роли, аудит и пользовательскую админку

При этом важно было не усложнить MVP избыточной распределённой архитектурой.

## Что было сделано

- спроектирована доменная модель лида, чата, пользователей и аудита
- реализован модульный монолит на `Next.js + Prisma`
- выделен отдельный `Socket.IO` процесс для real-time общения
- реализованы REST endpoints для лидов, чатов, авторизации и управления пользователями
- внедрены Telegram и Bitrix24 интеграции с фиксацией результата в `IntegrationLog`
- реализованы статусы лидов и чат-сессий
- реализованы роли `admin`, `operator`, `viewer` и `AuditLog`

## Архитектура

Архитектурно проект построен как модульный монолит с единым приложением `Next.js` и отдельным процессом `Socket.IO`.

Это решение позволило:

- быстро вывести MVP
- сохранить единый контекст доменной модели
- упростить развёртывание на VPS
- изолировать real-time слой без перехода к микросервисам

## Модель данных

Физически реализованы сущности:

- `Lead`
- `User`
- `ChatSession`
- `Message`
- `LeadEvent`
- `OperatorComment`
- `IntegrationLog`
- `AuditLog`

Дополнительно была продумана целевая модель развития с сущностями `Visitor`, `IntegrationJob`, `AnalyticsEvent`, `Settings`.

## API / WebSocket

REST API покрывает:

- создание лидов
- создание и восстановление чат-сессий
- handoff оператору
- управление статусами и комментариями
- авторизацию
- user management

WebSocket-контракт покрывает:

- подключение к чат-комнате
- exchange сообщений
- typing indicator
- presence
- уведомление о закрытии чата

## Интеграции

- Telegram Bot API для оперативного уведомления о новых лидах
- Bitrix24 CRM API для передачи заявок во внешнюю CRM
- Яндекс Метрика для фиксации целей и базовой маркетинговой аналитики

Во всех интеграциях реализовано логирование результата через `IntegrationLog`.

## Админка

В админке реализованы:

- список лидов и фильтры
- карточка заявки
- комментарии и история событий
- список чат-сессий
- real-time операторская панель
- аудит
- управление пользователями

## Аналитика

Система сохраняет:

- `utm_source`
- `utm_medium`
- `utm_campaign`
- `utm_content`
- `utm_term`
- `referrer`
- `landingPage`

Также поддерживаются события Яндекс Метрики по ключевым действиям пользователя.

## Безопасность

- админка защищена cookie-based сессией
- роли ограничивают изменяющие действия
- пароли хранятся только в виде hash
- `passwordHash` не возвращается на клиент
- действия пользователей записываются в `AuditLog`

## Результат

Получена рабочая MVP-система, которая покрывает полный цикл:

- захват лида
- диалог с потенциальным клиентом
- handoff на оператора
- уведомление во внешние каналы
- административную обработку
- базовый контроль и аудит

## Что можно развить дальше

- очередь интеграций и retry-механизм
- отдельную сущность `Visitor`
- расширенный RBAC
- внутренние `AnalyticsEvent`
- `Settings UI`
- более формальную модель SLA и операторской нагрузки
