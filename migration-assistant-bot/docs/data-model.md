# Модель данных — Migration Assistant Bot

Ниже описаны сущности, отражённые в ERD проекта.

## USERS
### Назначение
Хранит основную информацию о пользователе, который взаимодействует с чат-ботом.

### Ключевые поля
- `user_id` — внутренний идентификатор пользователя
- `external_chat_id` — идентификатор пользователя во внешнем канале общения
- `channel` — канал взаимодействия
- `name` — имя пользователя
- `phone` — телефон
- `created_at` — дата создания записи

### Связи
- один пользователь может иметь несколько лидов
- один пользователь может иметь несколько платежей
- один пользователь может иметь несколько покупок
- один пользователь может иметь несколько запросов на документы

### Бизнес-смысл
Это корневая сущность, от которой строятся покупки, заявки и платёжные сценарии.

## LEADS
### Назначение
Фиксирует лид, передаваемый в CRM после оплаты или завершения сценария заявки.

### Ключевые поля
- `lead_id` — идентификатор лида
- `user_id` — ссылка на пользователя
- `source` — источник лида
- `scenario` — сценарий, из которого сформирован лид
- `service_type` — тип услуги или направления
- `qualification_result` — результат квалификации
- `bitrix_lead_id` — идентификатор лида в CRM
- `status` — статус лида
- `created_at` — дата создания

### Связи
- лид принадлежит пользователю
- лид может быть связан с запросом на документ

### Бизнес-смысл
Сущность нужна для передачи и дальнейшей обработки целевых заявок менеджерами.

## PAYMENTS
### Назначение
Хранит информацию о платёжных операциях.

### Ключевые поля
- `payment_id` — внутренний идентификатор платежа
- `external_payments_id` — идентификатор платежа во внешней системе
- `user_id` — ссылка на пользователя
- `amount` — сумма
- `currency` — валюта
- `status` — статус платежа
- `confirmation_url` — ссылка на оплату
- `paid_at` — дата успешной оплаты
- `created_at` — дата создания

### Связи
- платёж принадлежит пользователю
- платёж может быть связан с покупкой

### Бизнес-смысл
Позволяет управлять выдачей результата и различать оплаченные и неуспешные сценарии.

## PRODUCTS
### Назначение
Хранит перечень цифровых продуктов и услуг, доступных в чат-боте.

### Ключевые поля
- `product_id` — идентификатор продукта
- `type` — тип продукта
- `category` — категория
- `name` — название
- `price` — стоимость
- `currency` — валюта
- `is_active` — признак доступности

### Связи
- продукт участвует в покупках
- продукт может быть связан с запросом на документ

### Бизнес-смысл
Эта сущность определяет, что именно пользователь может купить или заказать через чат-бот.

## PURCHASES
### Назначение
Фиксирует факт покупки продукта пользователем.

### Ключевые поля
- `purchase_id` — идентификатор покупки
- `user_id` — ссылка на пользователя
- `product_id` — ссылка на продукт
- `payment_id` — ссылка на платёж
- `status` — статус покупки
- `download_link` — ссылка на скачивание
- `download_sent_at` — время отправки ссылки
- `created_at` — дата создания

### Связи
- покупка связана с пользователем
- покупка связана с продуктом
- покупка связана с платежом

### Бизнес-смысл
Нужна для сценария продажи шаблонов и контроля факта выдачи цифрового результата.

## DOCUMENT_REQUESTS
### Назначение
Хранит заявки или запросы, связанные с подготовкой документа или оформлением услуги.

### Ключевые поля
- `request_id` — идентификатор запроса
- `user_id` — ссылка на пользователя
- `product_id` — ссылка на продукт
- `lead_id` — ссылка на лид
- `request_type` — тип запроса
- `payload_json` — данные, собранные в сценарии
- `generated_file_url` — ссылка на подготовленный файл, если он формируется
- `status` — статус запроса
- `created_at` — дата создания

### Связи
- запрос принадлежит пользователю
- запрос может быть связан с продуктом
- запрос может быть связан с лидом

### Бизнес-смысл
Эта сущность отражает сценарии заказа услуги и подготовки документов, где кроме оплаты важны собранные данные пользователя.
