# Интеграции — Migration Assistant Bot

## 1. YooKassa

### Назначение
Интеграция используется для создания платежей, получения ссылки на оплату, проверки статуса и обработки webhook по факту оплаты.

### Входные данные
- тип продукта или услуги
- название продукта
- сумма
- валюта
- идентификатор пользователя
- контактные данные пользователя

### Основные операции
- создание платежа через `POST /api/payments`
- получение `confirmation_url`
- проверка статуса через `GET /api/payments/{payment_id}`
- обработка webhook через `POST /api/webhooks/yookassa`

### Успешный результат
- создан платёж со статусом `pending`
- пользователю возвращена ссылка на оплату
- после `payment.succeeded` запускается post-payment сценарий

### Возможные ошибки
- некорректная сумма
- не передан тип продукта
- ошибка создания платежа
- webhook пришёл повторно
- статус платежа не подтверждён

### Бизнес-правила
- PDF выдаётся только после подтверждённой оплаты
- один webhook не должен обрабатываться повторно
- при неуспешной оплате пользователь не получает оплаченный результат

## 2. Bitrix24 CRM

### Назначение
Bitrix24 используется для фиксации лидов, сформированных после оплаты или после завершения сценария заявки.

### Входные данные
- имя пользователя
- телефон
- источник
- сценарий
- тип услуги или продукта
- идентификатор платежа, если он есть
- дополнительная информация по сценарию

### Сценарии создания лида
- успешная покупка шаблона
- успешная оплата услуги
- завершение сценария оставления заявки

### Успешный результат
- CRM возвращает идентификатор лида
- система фиксирует успешное создание

### Возможные ошибки
- CRM недоступна
- ошибка валидации данных в CRM
- лид не создан по технической причине

### Бизнес-правила
- лид должен создаваться только по завершённому бизнес-сценарию
- ошибка CRM не должна приводить к потере пользовательских данных
- сценарии покупки и заявки должны быть различимы в передаваемых данных

## 3. Telegram

### Назначение
Telegram используется для оперативного уведомления менеджера о новой заявке, покупке или подтверждённой оплате.

### Входные данные
- идентификатор лида или сценария
- имя пользователя
- телефон
- описание сценария
- служебный текст уведомления

### Когда отправляется
- после создания лида
- после покупки шаблона
- после оплаты услуги

### Что содержит
- краткий контекст сценария
- данные пользователя
- сведения о продукте или услуге
- служебный комментарий для менеджера

### Успешный результат
- сообщение доставлено менеджеру
- система получила подтверждение отправки

### Возможные ошибки
- Telegram API недоступен
- ошибка авторизации
- сообщение не отправлено

### Бизнес-правила
- уведомление не должно быть единственным местом хранения данных о лиде
- ошибка Telegram не должна блокировать создание лида в CRM
- уведомление должно отправляться после ключевого бизнес-события, а не до него
