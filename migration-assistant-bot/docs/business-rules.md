# Бизнес-правила — Migration Assistant Bot

- BR-001. PDF-документ выдаётся пользователю только после подтверждённой успешной оплаты.
- BR-002. Для покупки шаблона пользователь должен пройти сценарий выбора продукта и подтверждения оплаты.
- BR-003. Лид в CRM создаётся после подтверждённой оплаты продукта или услуги либо после завершения сценария заявки.
- BR-004. Один и тот же webhook не должен приводить к повторному выполнению бизнес-действий.
- BR-005. Повторный webhook не должен создавать дубль лида в CRM.
- BR-006. После создания лида менеджер должен получить уведомление в Telegram.
- BR-007. Для услуги после оплаты инициируется дальнейшая работа менеджера, а не автоматическая выдача PDF.
- BR-008. Для шаблона после подтверждённой оплаты пользователь должен получить цифровой результат автоматически.
- BR-009. Контактные данные пользователя должны быть собраны до создания платёжного сценария, если они нужны для дальнейшей обработки.
- BR-010. Пользователь должен дать согласие на обработку персональных данных до отправки заявки.
- BR-011. При ошибке создания лида в CRM пользовательский сценарий не должен терять собранные данные.
- BR-012. При ошибке отправки уведомления в Telegram лид всё равно должен считаться созданным, если CRM приняла данные.
- BR-013. При неуспешной оплате система не должна переводить сценарий в успешное завершение.
- BR-014. Статус оплаты должен определяться по данным платёжной системы, а не по действию пользователя в интерфейсе.
- BR-015. Создание платежа должно происходить только для выбранного продукта или услуги.
- BR-016. Каждому бизнес-сценарию должен соответствовать предсказуемый маршрут обработки после оплаты.
- BR-017. Система должна различать сценарии покупки шаблона, заказа услуги и оставления заявки при создании лида.
- BR-018. Источник заявки должен фиксироваться и передаваться в CRM.
- BR-019. Система должна сохранять результат квалификации пользователя в сценарии заявки.
- BR-020. Пользовательский сценарий не должен зависеть от успешности Telegram-уведомления.
