# Use Cases — Migration Assistant Bot

## UC-001. Онлайн-консультация
**Цель**  
Помочь пользователю выбрать тему вопроса и получить релевантный ответ.

**Акторы**  
Пользователь.

**Предусловия**  
Пользователь открыл чат-бот.

**Основной сценарий**  
1. Пользователь выбирает сценарий онлайн-консультации.  
2. Система показывает список тем.  
3. Пользователь выбирает тему.  
4. Система показывает ответ.  
5. Система предлагает следующий шаг.

**Альтернативные сценарии**  
- Пользователь не выбрал тему и возвращается на стартовый экран.  
- Пользователь после ответа переходит к заявке или консультации.

**Результат**  
Пользователь получает ответ и переводится к следующему действию.

## UC-002. Покупка шаблона
**Цель**  
Продать пользователю цифровой шаблон документа.

**Акторы**  
Пользователь, платёжная система, CRM.

**Предусловия**  
Пользователь выбрал ветку покупки шаблона.

**Основной сценарий**  
1. Пользователь выбирает шаблон.  
2. Система показывает описание продукта.  
3. Система собирает контактные данные.  
4. Система создаёт платёж.  
5. Пользователь оплачивает продукт.  
6. Система получает подтверждение оплаты.  
7. Система выдаёт PDF.  
8. Система создаёт лид в CRM.

**Альтернативные сценарии**  
- Платёж не создан.  
- Оплата не завершена.  
- CRM временно недоступна.

**Результат**  
Пользователь получает оплаченный PDF, лид создаётся в CRM.

## UC-003. Заказ услуги
**Цель**  
Оформить заказ услуги с предоплатой.

**Акторы**  
Пользователь, платёжная система, CRM, менеджер.

**Предусловия**  
Пользователь выбрал услугу.

**Основной сценарий**  
1. Пользователь выбирает услугу.  
2. Система собирает необходимые данные.  
3. Система запрашивает контактные данные.  
4. Система создаёт платёж.  
5. Пользователь вносит предоплату.  
6. Система получает подтверждение оплаты.  
7. Система создаёт лид.  
8. Система отправляет уведомление менеджеру.

**Альтернативные сценарии**  
- Пользователь не завершил оплату.  
- Сервис оплаты недоступен.  
- Уведомление менеджеру не отправлено.

**Результат**  
Заказ услуги зафиксирован, лид создан, менеджер уведомлён.

## UC-004. Оставление заявки
**Цель**  
Собрать квалифицированную заявку для менеджера.

**Акторы**  
Пользователь, CRM, менеджер.

**Предусловия**  
Пользователь выбрал сценарий заявки.

**Основной сценарий**  
1. Пользователь проходит анкетирование.  
2. Система сохраняет ответы.  
3. Пользователь оставляет контактные данные и согласие.  
4. Система формирует результат квалификации.  
5. Система создаёт лид в CRM.  
6. Система отправляет уведомление менеджеру.

**Альтернативные сценарии**  
- Пользователь не завершил анкету.  
- CRM недоступна.  
- Telegram недоступен.

**Результат**  
Лид создан и передан менеджеру в работу.

## UC-005. Обработка успешной оплаты
**Цель**  
Запустить корректную бизнес-логику после подтверждения оплаты.

**Акторы**  
YooKassa, backend, CRM, Telegram.

**Предусловия**  
Платёж существует и находится в ожидании подтверждения.

**Основной сценарий**  
1. YooKassa отправляет webhook `payment.succeeded`.  
2. Система проверяет, не обрабатывался ли платёж ранее.  
3. Система определяет сценарий оплаты.  
4. Система запускает нужный post-payment сценарий.  
5. Система создаёт лид и или отправляет результат пользователю.

**Альтернативные сценарии**  
- Webhook получен повторно.  
- Платёж не найден во внутренней системе.

**Результат**  
Успешная оплата приводит к корректному завершению бизнес-потока.

## UC-006. Ошибка оплаты
**Цель**  
Корректно обработать неуспешный платёж.

**Акторы**  
Пользователь, YooKassa.

**Предусловия**  
Пользователь перешёл к оплате.

**Основной сценарий**  
1. Пользователь не завершает оплату или платёж завершается ошибкой.  
2. Система получает статус `failed` или `canceled`.  
3. Система не выдаёт PDF и не переводит сценарий как успешно оплаченный.  
4. Система позволяет повторить оплату или вернуться назад.

**Альтернативные сценарии**  
- Статус оплаты остаётся `pending` длительное время.

**Результат**  
Платёж не приводит к выдаче результата, пока не подтверждён успешно.

## UC-007. Создание лида в CRM
**Цель**  
Передать результат сценария в Bitrix24.

**Акторы**  
Backend, Bitrix24 CRM.

**Предусловия**  
Есть данные пользователя и основание для создания лида.

**Основной сценарий**  
1. Система формирует payload лида.  
2. Система отправляет данные в CRM.  
3. CRM возвращает идентификатор лида.  
4. Система фиксирует успешное создание.

**Альтернативные сценарии**  
- CRM возвращает ошибку.  
- CRM недоступна.

**Результат**  
Лид создан либо зафиксирована ошибка интеграции без потери данных.

## UC-008. Уведомление менеджера
**Цель**  
Сообщить менеджеру о новой заявке, покупке или оплате.

**Акторы**  
Backend, Telegram.

**Предусловия**  
Сформирован лид или завершён ключевой бизнес-сценарий.

**Основной сценарий**  
1. Система формирует текст уведомления.  
2. Система отправляет сообщение менеджеру в Telegram.  
3. Система получает подтверждение отправки.

**Альтернативные сценарии**  
- Telegram недоступен.  
- Сообщение не доставлено.

**Результат**  
Менеджер получает уведомление либо ошибка фиксируется без остановки основного сценария.
