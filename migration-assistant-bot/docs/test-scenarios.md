# Тестовые сценарии — Migration Assistant Bot

## Консультация

### TC-001
**Название**  
Открытие сценария онлайн-консультации.

**Предусловия**  
Пользователь открыл чат.

**Шаги**  
1. Выбрать сценарий онлайн-консультации.  
2. Проверить список тем.

**Ожидаемый результат**  
Система показывает перечень доступных тем для консультации.

### TC-002
**Название**  
Получение ответа по теме консультации.

**Предусловия**  
Пользователь находится в консультационном сценарии.

**Шаги**  
1. Выбрать тему вопроса.  
2. Дождаться ответа.

**Ожидаемый результат**  
Система показывает ответ и предлагает следующий шаг.

### TC-003
**Название**  
Переход из консультации к следующему действию.

**Предусловия**  
Пользователь получил ответ по теме.

**Шаги**  
1. Выбрать предложенное следующее действие.

**Ожидаемый результат**  
Пользователь переводится в следующий релевантный сценарий.

### TC-004
**Название**

**Предусловия**

**Шаги**

**Ожидаемый результат**

### TC-005
**Название**  
Создание платежа для шаблона.

**Предусловия**  
Пользователь выбрал шаблон и ввёл контактные данные.

**Шаги**  
1. Подтвердить переход к оплате.

**Ожидаемый результат**

### TC-006
**Название**

**Предусловия**  
Платёж по шаблону подтверждён.

2. Дождаться обработки webhook.

**Ожидаемый результат**  
Пользователь получает PDF, лид создаётся в CRM.

### TC-007
**Название**

**Предусловия**  
Платёж создан, но не подтверждён.

**Шаги**  
1. Попробовать завершить сценарий без успешной оплаты.

**Ожидаемый результат**  
PDF не выдаётся.

## Оплата

### TC-014
**Название**  
Проверка статуса платежа.

**Предусловия**  
Платёж создан.

**Шаги**  
1. Запросить статус платежа по `payment_id`.

**Ожидаемый результат**  
Система возвращает актуальный статус платежа.

### TC-015
**Название**  
Обработка статуса `pending`.

**Предусловия**  
Платёж существует, но ещё не подтверждён.

**Шаги**  
1. Проверить статус платежа до завершения оплаты.

**Ожидаемый результат**  
Система сохраняет сценарий в ожидании подтверждения.

### TC-016
**Название**  
Обработка статуса `canceled`.

**Предусловия**  
Платёж отменён пользователем или системой.

**Шаги**  
1. Получить отменённый статус платежа.

**Ожидаемый результат**  
Сценарий не переводится в успешный, PDF не выдаётся.

**Предусловия**

**Ожидаемый результат**  
Система не создаёт дубль лида и не повторяет бизнес-действия.

## CRM

### TC-019
**Название**

**Предусловия**

**Шаги**

**Ожидаемый результат**  
CRM возвращает идентификатор лида.

**Предусловия**

## Негативные сценарии

### TC-023
**Название**  
Не передан тип продукта при создании платежа.

**Предусловия**  
Пользователь инициирует оплату.

**Шаги**  
1. Отправить запрос на создание платежа без `product_type`.

**Ожидаемый результат**  
Система возвращает ошибку создания платежа.

### TC-024
**Название**  
Некорректная сумма платежа.

**Предусловия**  
Идёт попытка создания платежа.

**Шаги**  
1. Отправить некорректную сумму.

**Ожидаемый результат**  
Система отклоняет создание платежа.

### TC-025
**Название**  
Платёжный сценарий без `confirmation_url`.

**Предусловия**  
Платёж создаётся через интеграцию.

**Шаги**  
1. Смоделировать ответ без ссылки на оплату.

**Ожидаемый результат**  
Пользователь не переводится к успешному платёжному шагу, ошибка фиксируется.
